# AGENTS.md — shielded-chips

**Verified against:** Compact language `0.23`, compiler `0.31.1`,
`@midnight-ntwrk/midnight-js-*` `4.1.1`, wallet SDK `1.2.0`, Node 22.

## What it teaches

- **Shielded tokens end to end**: minting a coin (`mintShieldedToken`) with a
  caller-supplied *secret* nonce, paying it to a wallet or contract
  (`sendShielded`), a contract taking custody (`receiveShielded` +
  `Map.insertCoin`), and spending it back out.
- **MIP-0011 conformance** — `chips.compact` is a Native Shielded Token
  (Fungible profile, supply-accounting extension) with both burn paths:
  transient (`sendImmediateShielded`) for a same-tx coin, Merkle
  (`sendShielded`) for a contract-held one.
- `ShieldedCoinInfo` vs `QualifiedShieldedCoinInfo`, and
  `Either<ZswapCoinPublicKey, ContractAddress>` recipients.
- **Keeping coin nonces out of public state.** Any coin nonce on the ledger is a
  linkability oracle for the wallet that funded or received it. Roulette stores
  a `persistentCommit` of the escrowed coin (not the coin), and `claimWinnings`
  passes the player's secret coin as `mergeCoin`'s **first** argument, because
  the merged nonce derives from the first input.
- A per-dapp pseudonym derived from a witness secret (no `ownPublicKey()`), and
  access control via a proof-bound commitment check.
- A commit/reveal on the winning number.
- Wiring **two contracts** from TypeScript: separate compiled artifacts and ZK
  config paths, one shared private-state shape and `localSecretKey` witness.

## Layout

- `contract/chips.compact` — MIP-0011 shielded token; only the house mints/burns.
- `contract/roulette.compact` — RED/BLACK game; custodies chip coins, pays 2×.
- `contract/index.ts` — `CompiledChipsContract` / `CompiledRouletteContract`
  and their zk-config paths; `contract/witnesses.ts` — shared witnesses.
- `src/wallet.ts` adds `splitShieldedCoin` (a self-transfer that re-nonces a
  coin so the issuer can no longer recognise it).
- `src/test/roulette.test.ts` — the full functional round (3 wallets).
- `src/test/privacy.test.ts` — one round, then mechanically asserts that the
  captured secrets (escrow nonce, payout nonce, wallet key) are absent from
  both contracts' public ledger state.
- `TUTORIAL.md` (walkthrough of writing both contracts), `LESSONS.md` (privacy
  audit of an earlier version), `privacy-tests.md` (what the privacy suite
  checks, latest results). Keep them in sync when contracts or tests change.

## Run

```bash
yarn compile          # writes contract/managed/{chips,roulette}
yarn env:up && yarn wait:dust
yarn test:local
yarn env:down
```

## Notes for agents

- `contract/managed/` is generated by `yarn compile` and gitignored. The TS
  harness imports from it, so nothing type-checks until you have compiled at
  least once.
- This example deviates from the single-contract template: `compile` builds
  two contracts, and the circuit-id union in `src/providers.ts` is the union of
  both contracts' `keyof ImpureCircuits`. Build one provider set per
  (wallet, contract) — `NodeZkConfigProvider` resolves keys under one
  `managed/<contract>/` directory — and pass a distinct `storeSuffix`.
- The chip color is `rawTokenType(domain, chipsAddress)` computed off chain;
  MIP-0011 forbids precomputing it in the constructor.
- The contract never stores a player's escrowed coin, so the player replays it
  from private state at claim/forfeit time. Its `mt_index` is recovered from the
  bet transaction's `zswapStartIndex` via the indexer (`escrowMtIndex` in the
  tests) and written with `rememberEscrow`.
- Wallet roles: Alice (house) / Bob / Charlie via
  `resolveWallet(network, role)`. Both test files share Alice and Bob, so
  `vitest.config.ts` sets `fileParallelism: false`.
