# AGENTS.md — battleship

**Verified against:** Compact language `0.23`, compiler `0.31.1`,
`@midnight-ntwrk/midnight-js-*` `4.1.1`, wallet SDK `1.2.0`, Node 22.

## What it teaches

- A **Compact contract as a state machine**.
- **Role-based access control** on circuits.
- **Private state** — setters, getters, modifiers — and defending against
  **malicious private-state manipulation**.
- **On-chain verification of off-chain data**.
- Operations on a `List` and intermediate witness functionality.

## Layout

- `contract/battleship.compact` (committed), `contract/index.ts`,
  `contract/witnesses.ts`.
- `src/` harness; `src/test/battleship.test.ts`.
- `ui/`: browser frontend generated by `yarn new:ui battleship` (persistent
  private state; see `ui/AGENTS.md` and `ui/README.md`). Game logic for the
  UI is in `ui/src/midnight/battleship-api.ts`, and
  `ui/src/__tests__/battleship-circuits.test.ts` replays this example's Node
  test in memory.

## Run

```bash
yarn compile
yarn env:up && yarn wait:dust
yarn test:local
yarn env:down
```

## Notes for agents

- `contract/managed/` is generated by `yarn compile` and gitignored.
- `contract/witnesses.ts` is imported by the browser too. Keep it free of
  `node:*` imports (the generator refuses otherwise).
- The player's `sk` is their identity (`getDappPubKey(sk)` is stored as
  `player1`/`player2`), so the UI must never re-create private state for a
  game it already has. See "Rejoining" in `ui/AGENTS.md` §5.
