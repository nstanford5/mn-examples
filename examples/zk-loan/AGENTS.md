# AGENTS.md — zk-loan

**Verified against:** Compact language `0.23`, compiler `0.31.1`,
`@midnight-ntwrk/midnight-js-*` `4.1.1`, wallet SDK `1.2.0`, Node 22.

## What it teaches

- Processing sensitive data (credit score, income, tenure) **privately**: it is
  supplied by a witness and only the tier outcome (`LoanStatus`,
  `authorizedAmount`) is `disclose`d to the ledger.
- **Verifying an off-chain attestation in-circuit**: a registered provider
  Schnorr-signs the profile on Jubjub; `schnorr.compact` verifies it inside the
  proof, so a tampered profile cannot pass. Includes a witness-assisted
  challenge reduction whose quotient is range-bounded (a soundness fix with a
  regression test).
- **Witness-derived identity**: one 32-byte `userSecretKey` in private state
  yields both the admin key (`deriveAdminPublicKey`) and a PIN-bound,
  rotatable user key (`deriveUserPublicKey`) via domain-separated
  `persistentHash`. `ownPublicKey()` is never used.
- Multi-file Compact: a `module` in `schnorr.compact` imported with a prefix.
- Nested ledger ADTs (`Map<Bytes<32>, Map<Uint<16>, LoanApplication>>`),
  admin-gated circuits, admin rotation by public key only.
- Fixed-size batching (`for i of 0..5`) with an on-chain cursor to migrate a
  variable number of loans across several transactions (`changePin`).

Ported from [midnightntwrk/example-zkloan](https://github.com/midnightntwrk/example-zkloan)
(contract, simulator tests, the attestation API, and the UI). The CLI is not
ported.

## Layout

- `contract/zk-loan.compact` + `contract/schnorr.compact` (committed),
  `contract/index.ts`, `contract/witnesses.ts`.
- `src/` harness. Two suites, both picked up by `yarn test`:
  - `src/test/zk-loan.simulator.test.ts` — 62 contract unit tests against the
    in-memory simulator (`src/test/zk-loan.simulator.ts`); no network needed:
    `npx vitest run src/test/zk-loan.simulator.test.ts`.
  - `src/test/zk-loan.test.ts` — on-chain deploy/call flow via midnight-js.
  - `src/test/attestation-api/*.test.ts` — HTTP and signing tests for the
    attestation API (port 0, no network).
- `attestation-api/` — the attestation provider as a restify service
  (`POST /attest`, `GET /provider-info`, `GET /health`). `signing.ts` is the
  off-chain Schnorr signer; run standalone with `yarn attestation:start`
  (env: `PORT`, `PROVIDER_ID`, `PROVIDER_SECRET_KEY`, `NETWORK_ID`).
- `ui/` — React/Vite front end, its own workspace
  (`@midnight-ntwrk/example-zk-loan-ui`, root glob `examples/*/ui`). Not in
  CI: it needs a Lace wallet. Verify changes with `yarn build` in `ui/`
  (typecheck + bundle). See `ui/README.md` for the browser-specific gotchas.
- `src/test/utils/test-data.ts` — fixtures for the simulator tests
  (`createCustomSignedProfile`), signing in-process via
  `attestation-api/signing.ts`.

## Run

```bash
yarn compile
yarn env:up && yarn wait:dust
yarn test:local
yarn env:down
```

## Notes for agents

- `ui/` pins upstream's Vite 6, which Yarn hoists to the repo root, so every
  example's `vitest.config.ts` resolves Vite 6.4.3 for `loadEnv`. Deliberate.
  See the root `AGENTS.md` and the TODO in `ui/README.md`.

- `contract/managed/` is generated by `yarn compile` and gitignored. The TS
  harness imports from it, so nothing type-checks until you have compiled at
  least once.
- The circuit-id union in `src/providers.ts` is derived from the compiled
  contract (`keyof ImpureCircuits`), so it never needs editing when circuits
  change.
- The signed message is `[creditScore, monthlyIncome, monthsAsCustomer,
  transientHash(deriveUserPublicKey(secret, pin))]`. A signature is bound to one
  (secret, PIN) pair — re-sign after changing either, or `requestLoan` fails
  with "Invalid attestation signature".
- Off-chain signers must use `pureCircuits.schnorrChallenge` and reduce it
  `mod 2^248`, and the response `mod` the Jubjub order — see `schnorrSign`.
- The on-chain suite starts the attestation API in-process on an ephemeral
  port, registers the key from `/provider-info`, and gets every borrower
  signature from `/attest`. The API is sent only
  `transientHash(deriveUserPublicKey(secret, pin))`, never the secret or PIN.
- The attestation API is demo-grade: it signs whatever figures it is sent.
  The contract only proves the registered provider vouched for them.
- restify 11 (matching upstream) logs a harmless `DEP0111` deprecation
  warning on Node 22.
- The on-chain suite uses ONE wallet (Alice) for fees and two private-state
  ids (`AliceZkLoanState`, `BobZkLoanState`) for two contract identities —
  identity here is the witness secret, not the paying wallet.
- A circuit assertion failure (non-admin, blacklisted, bad signature) rejects
  `submitCallTx` locally before anything is submitted.
- Remote-network wiring is shared, not copied. `src/wallet.ts` takes an optional
  `{ fastSync }` and the test resolves its wallet with
  `resolveWallet(network, role)` from `@midnight-ntwrk/example-fast-sync`. Do not
  write a per-example seed resolver; the shared one knows every suite's role
  names and reads the repo-root `.env.<network>`. See `FAST-SYNC.md`.
